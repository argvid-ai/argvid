# Repository scope

This repository is a complete public engineering workspace. Inclusion is decided by public purpose, self-containment, reproducibility, and publication rights, not by whether a component is a small reference or a complete project.

## Placement outcomes

- `ACCEPT_IN_PUBLIC_REPOSITORY`
- `EXCLUDE_FROM_PUBLIC_REPOSITORY`

These are the only placement outcomes. Missing evidence, unresolved rights, or an unsafe publication boundary means exclusion until resolved. Exclusion stops copying, implementation using excluded inputs, and publication here. The result is reported separately from the [Agent handshake](../AGENTS.md).

## Inclusion bases

A contribution must identify at least one basis:

1. Stable interoperability contracts.
2. Reproducible reference implementations.
3. Conformance/safety/performance validation.
4. Complete public project delivery.
5. Open-source governance/docs/tooling.

A proposal toward a stable contract can qualify without pretending to be released. A complete public app or device project can qualify when source, setup, required inputs, tests, evidence, and licenses are publicly reviewable. The [project framework](PROJECTS.md) provides its delivery boundary.

## Exclusion and review

Exclude credentials, personal or restricted media/data, confidential implementation, undisclosed dependencies, materials without publication rights, and unreproducible claims. Review source code, documentation, fixtures, model weights, datasets, assets, and hardware sources separately. Do not include material merely because an Agent can read it or an account can push it.

[Publication review](PUBLICATION_POLICY.md) happens before the first public push. A passing checker is evidence of structure, not legal permission or a guarantee of safety.
