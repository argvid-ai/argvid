# Architecture decisions

## Responsibility

Record accepted, superseded, or deprecated decisions that future contributors and agents must follow.

## Non-goals

Raw discussion, unreviewed proposals, business planning, or transient task notes.

## Inputs and outputs

Inputs are reviewed RFCs or explicit maintainer decisions; outputs are dated decision records with consequences.

## Dependencies

Depends on evidence, affected contracts, and repository governance.

## Invariants

Decisions are immutable history: supersede them with a new record rather than rewriting rationale.

## Start condition

Add a record when a durable choice constrains future implementation or compatibility.

## Ownership and review

Maintainer plus owners of affected modules.

## Verification

Repository context, code, and tests must not contradict accepted decisions.

## Public use cases

Keep accepted public engineering choices and their consequences readable without external organizational context.

## License and data

Source and documentation default to Apache-2.0. Use synthetic or explicitly licensed public inputs with recorded provenance; publication rights require human review. Third-party assets, weights, datasets, and hardware design sources need separate license review. This documented boundary is not an activated implementation, released compatibility guarantee, or completed HIL result.
