## Evidence and redistribution boundary

`docs/dependencies.tsv` records each Maven coordinate, declared license names/URLs, the POM coordinate supplying those licenses (including inherited parent declarations), SHA-256 of the inspected component POM, and verified artifact filenames. Maven coordinate `group:artifact:version` maps to `group/with/slashes/artifact/version/artifact-version.pom`; Google artifacts use `https://dl.google.com/dl/android/maven2/`, other Maven artifacts use `https://repo.maven.apache.org/maven2/`, and plugin markers are also resolvable through `https://plugins.gradle.org/m2/`. The configuration in `src/settings.gradle.kts` is authoritative for repository resolution. No credentials are needed.

`src/gradle/verification-metadata.xml` contains SHA-256 entries generated by resolving this reduced build's Gradle configurations, including compile, test, lint, plugins, and platform tool variants. It does not contain an imported full catalog or excluded application dependency configuration. Regeneration is a trust-establishment operation: review fetched artifacts and checksums before committing it. Strict verification checks against these recorded bytes; it is not independent signature verification, license approval, or a supply-chain guarantee. The wrapper JAR was separately checked against Gradle's published SHA-256 (see verification).

POM declarations can describe dual licenses or bundled code. The inventory preserves those declarations instead of choosing a legal interpretation. Non-Apache build/test transitives include MPL-1.1, EPL/EDL, CDDL/GPL-with-classpath-exception, LGPL/Apache dual declarations, MIT, Bouncy Castle and JDOM terms, BSD and public-domain declarations. Android tooling can include SDK-license artifacts. No such dependency binaries are vendored here except the Gradle wrapper; build products must receive their own binary-distribution notice review.

Three metadata-only parent POMs (`net.java:jvnet-parent:3`, `org.sonatype.oss:oss-parent:7`, `org.sonatype.oss:oss-parent:9`) contain no explicit license declaration. They have no executable artifacts in this inventory. This gap is preserved for human review, not silently marked approved. No proprietary/restricted image or model input is required. Publication rights for the delivered source and authored fixtures remain a separate reviewer responsibility.

For redistributions, retain upstream copyright statements, supplied LICENSE/NOTICE files and attribution, document modifications where required, and satisfy the actual component license (including any source-offer/source-availability requirements). Do not redistribute Android SDK/JDK/Apple tooling merely because a build uses it. The wrapper license and notice copies are provided in `notices`; they do not authorize SDK redistribution.

The camera-core AAR's included LICENSE contains Apache text, while its POM additionally declares BSD-3-Clause for libyuv. The separate `notices/libyuv-BSD-LICENSE.txt` preserves the [upstream libyuv notice text](https://chromium.googlesource.com/libyuv/libyuv.git/+/d694f0a82b4da9d8ea37e6c453b7a34947eb5790/LICENSE). That immutable reference identifies the notice text only, not the exact libyuv source revision inside CameraX; binary-release review must verify the bundled native-code notice completeness.

## Authored inputs and modifications

The source package adapts only local app composition, storage scope, deletion presentation, permissions, product labels and synthetic fixture generation. Third-party binaries are not modified. Numbered JPEG color bars and launcher vectors are generated/authored project geometry without images, fonts, people or private content; see [fixture provenance](fixtures/README.md). Unit-test IDs, times, byte arrays and content URIs are synthetic. No external account or asset access is needed to build or test.
