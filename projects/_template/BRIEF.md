# Project brief instructions

Status: proposed; implementation and release are not authorized by this template.

For upstream activation, an Issue or maintainer-approved public-safe task brief must supply the current objective, non-goals, acceptance checks, affected layers/planes, planned files, maintainer scope confirmation, required reviews, and next handoff. Replace these instructions in the copied project with that public task scope. Personal local experiments need no upstream scope approval but do not activate an accepted project. Missing required authority stops upstream implementation; a task packet cannot override accepted architecture or accept a protocol draft.

Record actual verification separately from planned tests. Unrun simulation, host, or HIL checks remain pending. Re-handshake when the task or authoritative context changes. Publication review precedes the first public push.

Use [the generic task/report fields](../../docs/TASK_HANDOFF.md). Retain public engineering facts here, not chats, full Agent prompts, or personnel details. Recipient-specific reports stay outside the repository.
