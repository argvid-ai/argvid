# Hardware tests

## Responsibility

Document repeatable mechanical, electrical, thermal, and motion-safety checks for the reference device.

## Non-goals

Formal certification, undocumented visual inspection, or claims based only on simulation.

## Inputs and outputs

Inputs are assembled reference hardware and test procedures; outputs are measurements, evidence, and explicit pass, fail, or pending states.

## Dependencies

Depends on approved hardware revisions, firmware, and safety limits.

## Invariants

Results identify hardware revision, procedure revision, operator, and measurement equipment.

## Start condition

Start when the first assembly and approved safety plan exist.

## Ownership and review

Hardware test owner with safety review.

## Verification

Second-person reproduction and traceable evidence for every claimed result.

## Public use cases

Reproduce mechanical, electrical, and motion-safety evidence with identified public hardware revisions.
